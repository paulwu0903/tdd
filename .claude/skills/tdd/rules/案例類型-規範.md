# Rule 1 - TDD Slice 與 NFR 量測卡的紅燈須失敗 [MUST]
- 案例卡的案例類型為 TDD Slice 或 NFR 量測時，紅燈寫完的測試執行結果必須是失敗，才算完成。
- NFR 量測卡的測試執行後已達標時是例外，記錄量測值即完成紅燈。

## Good Example
- TDD Slice 卡的新測試因行為尚未實作而失敗；NFR 量測卡已達標，記下量測值後結束紅燈。

```
T011 `/tdd 紅燈` SL-007（TDD Slice）
執行：pytest backend/tests/test_chat.py -k sl_007 → 1 failed（POST 空白訊息回 201，期望 422）
判定：紅燈完成

T042 `/tdd 紅燈` SL-025（NFR 量測）
執行：npx playwright test chat-nfr.spec.ts -g SL-025 → passed，20 則最大延遲 1.4 秒（門檻 2 秒）
判定：已達標，記錄 1.4 秒，紅燈完成
```

## Bad Example
- TDD Slice 卡的新測試一寫就通過，仍當作紅燈完成，這個測試從沒證明過它抓得到錯誤實作。

```
T011 `/tdd 紅燈` SL-007（TDD Slice）
執行：pytest backend/tests/test_chat.py -k sl_007 → 1 passed
判定：紅燈完成
```

# Rule 2 - 防回歸與旅程卡的紅燈須通過，失敗即回報 [MUST]
- 案例類型為防回歸（預期不先紅）或旅程（預期不先紅）時，紅燈寫完的測試執行結果必須是通過，才算完成。
- 測試失敗代表前面任務的實作有缺口：不在紅燈任務中補實作，把失敗的測試名稱、錯誤輸出與推斷的缺口位置回報給呼叫者。

## Good Example
- 防回歸卡的測試失敗，未動實作，直接回報缺口。

```
T009 `/tdd 紅燈` SL-005（防回歸（預期不先紅））
執行：pytest backend/tests/test_chat.py -k sl_005 → 1 failed（送出訊息後回合截止時間被重設）
處理：不改 backend/app/chat.py
回報：SL-005 失敗，推斷 T004 實作的送出訊息路徑更新了 turn_started_at，屬前面實作的缺口
```

## Bad Example
- 防回歸卡的測試失敗，在紅燈任務裡順手改了實作讓它通過，缺口被吞掉而沒有回報。

```
T009 `/tdd 紅燈` SL-005（防回歸（預期不先紅））
執行：pytest backend/tests/test_chat.py -k sl_005 → 1 failed
處理：修改 backend/app/chat.py，不再更新 turn_started_at → 1 passed
判定：紅燈完成
```
