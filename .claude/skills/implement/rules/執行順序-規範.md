# Rule 1 - 一個子代理只負責一個任務 [MUST]
- 一個子代理（平行執行緒）只接一個任務，一個任務就是一個 to do；不得在同一個子代理內順手實作其他任務，也不得把一個任務拆給多個子代理。
- 判準：子代理回報中的任務編號只有一個，修改的檔案都能對回該任務列的路徑或列入「任務路徑之外新增或修改的檔案」。

## Good Example
- 一批兩個 [P] 環境任務，各由一個子代理處理，各自回報。

```
批次：T001 [P]（backend/pyproject.toml）、T002 [P]（frontend/playwright.config.ts）
子代理 A → 只做 T001，回報 T001 的五項
子代理 B → 只做 T002，回報 T002 的五項
```

## Bad Example
- 子代理 A 做完 T001 後順手把 T002 的設定也改了，子代理 B 的產出被覆寫，T002 的回報對不上實際檔案。

```
子代理 A → 做 T001，並順手修改 frontend/playwright.config.ts（T002 的檔案）
子代理 B → 做 T002，回報與檔案現況不符
```

# Rule 2 - 依序走完該任務的每一步，不得略過 [MUST]
- 帶 `/tdd <步驟>` 標記的任務，依 tdd skill 該步驟的 SOP 從第一步走到最後一步。
- 其餘任務依序走完：讀 Must Read 部位 → 讀要 import 或修改的既有程式檔 → 實作 → 執行驗證指令 → 回讀 Why 驗收 → 五項回報。
- 任一步做不到時不得略過而進入下一步；依規範裁決或修正後補完該步，仍做不到則在回報中寫明卡在哪一步與原因。

## Good Example
- 每一步都有對應的實際動作，順序與上列一致。

```
T001 `環境` 加入負載量測的依賴與 pytest marker 於 backend/pyproject.toml
1. 讀 research.md › R4 › 負載量測、techstack.md › Dev Dependencies
2. 讀 backend/pyproject.toml 既有的 [tool.pytest.ini_options]
3. 加入 locust 依賴與 load marker
4. 執行 lint / typecheck / test → 全過
5. 回讀 Why「負載量測要和一般 API E2E 分開」→ 一般 test 指令已排除 load marker，通過
6. 回報五項
```

## Bad Example
- 略過讀既有檔與 Why 驗收，測試一綠就直接回報。

```
T001
1. 讀 research.md › R4 › 負載量測
2. （未讀 backend/pyproject.toml）直接新增一段 [tool.pytest.ini_options]，與既有段落重複
3. 執行 test → 全過
4. （未回讀 Why）回報「完成」
```
