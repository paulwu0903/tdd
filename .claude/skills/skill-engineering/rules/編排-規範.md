# Rule 1 - 步驟與剩餘來源都要有去向 [MUST]
- 步驟描述中除動詞、動作與部件路徑以外的內容（判斷、格式、演算法），以及未被任何步驟吸收的來源，每一項都要標出去向：進 script、進 rule、進 template、留在步驟，或由使用者決定捨棄。
- 標不出去向的不得靜默省略，列為待使用者決定。

## Good Example
- 下方 Bad Example 的改良版：步驟內的兩個判斷與剩餘來源 S7 都有去向。

```
Phase 2 第 1 步：WRITE 產出週報，數字保留兩位小數，結論段須說明風險。
  「數字保留兩位小數」                → rule
  「結論段須說明風險」                → rule
S7「週報固定分四段」（未進任何步驟）   → template
```

## Bad Example
- 步驟內的判斷與 S7 都沒有去向，施工後會無聲消失。

```
Phase 2 第 1 步：WRITE 產出週報，數字保留兩位小數，結論段須說明風險。
  （未標）
S7「週報固定分四段」（未進任何步驟）   → （未標）
```

# Rule 2 - 依內容型態選 deriver [MUST]
- 每一項內容依下表決定去向；同一步同時含機械動作與判斷時，先拆成兩步再各自歸類。

| 內容型態 | 判準 | 去向 |
|---|---|---|
| 機械動作 | 可決定性、輸入輸出明確、交給程式能加速且不損準確 | skill-derive-script |
| 判斷 | 需要 Good / Bad 案例才能無歧義套用 | skill-derive-rule |
| 產出格式 | 約束的是產出檔案長什麼樣 | skill-derive-template |
| 門檻判斷 | 一句話即可無歧義執行，不需案例 | 留在步驟 |

## Good Example
- 「取最大編號加一」可決定性，抽 script；「不列 getter / setter」有灰色地帶需案例，抽 rule；「未確認前停止」一句話可執行，留在步驟。

```
「NN 接續既有兩位數編號」          → skill-derive-script
「關鍵方法不列 getter / setter」   → skill-derive-rule
「未獲明確確認前停止，不寫程式」    → 留在步驟
```

## Bad Example
- 「收斂類別」是權衡，寫成程式會犧牲準確，卻歸到 script；「未確認前停止」不需案例，卻抽成 rule。

```
「拆解功能並收斂類別與關係」        → skill-derive-script
「未獲明確確認前停止，不寫程式」    → skill-derive-rule
```

# Rule 3 - 施工順序為 prune、script、rule、template [MUST]
- 施工表依 pass 排序：先所有 prune 列，再所有 script 列、rule 列，最後 template 列。
- prune 列的 Deriver 依捨棄範圍決定：整檔捨棄的部件寫「刪除檔案」；只捨棄部分 Rule 的規則檔寫「skill-form-rule（重寫）」。
- prune 先於其他 pass，否則 derive-rule 的「已被既有 Rule 涵蓋者剔除」會讓該刪的規則繼續存活；SOP 已於施工前依預覽寫成終態，script、rule、template 的接回依各自接回規範的「已指定則不改」不再改動步驟，三者順序只為固定施工表的排列，目標步驟編號一律以 SOP 預覽為準。

## Good Example
- 先刪舊 Rule 2，再抽新 rule；script、rule、template 列只為固定排列而依序排好，各列的目標步驟編號依 SOP 預覽。

```
| # | Pass     | 目標步驟        | Deriver                   |
| 1 | prune    | —               | skill-form-rule（重寫）   |
| 2 | script   | Phase 2 第 1 步 | skill-derive-script       |
| 3 | rule     | Phase 2 第 2 步 | skill-derive-rule         |
| 4 | template | Phase 2 第 2 步 | skill-derive-template     |
```

## Bad Example
- rule 列在 prune 前，新 rule 被尚未刪除的舊 Rule 2 判定為已涵蓋而剔除，舊 Rule 2 之後才被刪，結果兩條都不在。

```
| # | Pass     | 目標步驟        | Deriver                   |
| 1 | rule     | Phase 2 第 2 步 | skill-derive-rule         |
| 2 | prune    | —               | skill-form-rule（重寫）   |
```

# Rule 4 - 施工表每列指回來源編號 [MUST]
- 每列的萃取內容都要指回來源清單中的編號；指不回的不列入施工表，改為向使用者提出。

## Good Example
- 每列都有來源編號。

```
| # | Pass | 目標步驟        | Deriver           | 萃取內容         | 來源 |
| 1 | rule | Phase 2 第 1 步 | skill-derive-rule | 數字保留兩位小數 | S3   |
```

## Bad Example
- 第 2 列「結論段附圖表」在來源清單中找不到，是撰寫者自行加上的。

```
| # | Pass | 目標步驟        | Deriver           | 萃取內容         | 來源 |
| 1 | rule | Phase 2 第 1 步 | skill-derive-rule | 數字保留兩位小數 | S3   |
| 2 | rule | Phase 2 第 1 步 | skill-derive-rule | 結論段附圖表     | （無）|
```

# Rule 5 - 已被既有部件涵蓋的內容不列入施工表 [MUST]
- 步驟已點名的 rule、template 或 script 已能處理的內容，不再開施工列；只有既有部件尚未涵蓋的來源才列。
- 已完整模組化且沒有新來源的 skill，施工表為空。

## Good Example
- 既有規則檔已含「兩位小數」，不列；新來源 S9「結論段須說明風險」未被涵蓋，列為追加。

```
步驟：WRITE 依 `rules/Report-規範.md` 產出週報。
既有 Rule 1：數字保留兩位小數
| 1 | rule | Phase 2 第 1 步 | skill-derive-rule | 結論段須說明風險 | S9 |
```

## Bad Example
- 既有規則檔已含「兩位小數」，仍再開一列抽同一條。

```
步驟：WRITE 依 `rules/Report-規範.md` 產出週報。
既有 Rule 1：數字保留兩位小數
| 1 | rule | Phase 2 第 1 步 | skill-derive-rule | 數字保留兩位小數 | S3 |
```

# Rule 6 - 捨棄只限根因影響範圍 [MUST]
- 優化時，只有「造成根因」或「為根因補償而存在」的舊來源才能捨棄，去向寫成 `捨棄 ← 根因 N`。
- 其他舊來源預設保留；改動大小由根因深度決定，不由預期寬窄決定。

## Good Example
- 根因 1 是第 1 步缺 --since；S4 的規則是為了補償少讀而加的，捨棄；S6 與根因無關，雖然預期沒提到也保留。

```
根因 1：Phase 1 第 1 步缺 --since，少讀 commit
| 編號 | 原文                          | 去向            |
| S4   | Rule 3 不得編造 log 以外的項目 | 捨棄 ← 根因 1   |
| S6   | changelog 依 commit 類型分組   | Phase 1 第 2 步 |
```

## Bad Example
- S6 與根因無關，只因預期沒提到就被捨棄，優化範圍擴散到整份 skill。

```
根因 1：Phase 1 第 1 步缺 --since，少讀 commit
| 編號 | 原文                          | 去向                  |
| S4   | Rule 3 不得編造 log 以外的項目 | 捨棄 ← 根因 1         |
| S6   | changelog 依 commit 類型分組   | 捨棄 ← 不在預期內     |
```

# Rule 7 - 不以禁止規則回應症狀 [MUST]
- 施工表中新增 rule 的列，其萃取內容若只是把症狀改寫成禁止句，且根因類型不是「判斷缺規則」，不得列入。
- 改動落在根因所在的步驟或部件：步驟缺輸入改 SOP 預覽中的該步，樣板錯誤改樣板，script 錯誤改 script。

## Good Example
- 根因是步驟缺輸入，改動在 SOP 預覽的第 1 步補參數，施工表沒有 rule 列。

```
根因 1：步驟缺輸入（Phase 1 第 1 步缺 --since）
SOP 預覽：1. DELEGATE 以 uv run 執行 scripts/git_log.py --since <起點>，取得區間內全部 commit。
施工表：（無 rule 列）
```

## Bad Example
- 根因明明是步驟缺輸入，施工表卻開一列把症狀寫成禁止規則，第 1 步照樣少讀。

```
根因 1：步驟缺輸入（Phase 1 第 1 步缺 --since）
| 1 | rule | Phase 1 第 2 步 | skill-derive-rule | 不得包含 git log 以外的項目 | 症狀 |
```
