# Rule 1 - 每個前端介面都有對應段落 [MUST]
- plan.md 中端點類型為 `前端端點` 的每個介面，都要在 frontend.md 有對應段落，名稱一字不差。
- 共通介面（如 `前端共通介面`）獨立成一節 `## <介面名稱>`；其他介面在其畫面的「對應介面」標示。
- plan.md 沒有共通介面時，不寫共通介面一節。
- spec.md 需要的畫面在 plan.md 沒有對應的前端介面時，不自行編造介面名稱，回傳給呼叫端，由使用者決定是否回到 system-analysis 補盤點。

## Good Example
- 共通介面獨立成節，頁面介面以「對應介面」標示。

```
## 前端共通介面
### 結帳頁
- 對應介面：`結帳頁面介面`
```

## Bad Example
- 畫面沒有標對應介面，名稱也改寫了，回檢時對不回 plan.md。

```
### 結帳頁
- 對應：結帳
```

# Rule 2 - 呼叫以契約名稱引用並寫出畫面反應 [MUST]
- 呼叫 HTTP API 的操作寫在「操作｜呼叫｜成功時｜失敗時」表，「呼叫」欄的第一個程式碼片段寫 openapi.yaml 的 operationId；不寫 URL 或 HTTP method。
- 透過即時連線送出訊息的操作寫在「操作｜送出訊息｜受理時｜拒絕時」表，「送出訊息」欄的第一個程式碼片段寫 asyncapi.yaml 的 message 名稱。
- 伺服器推播的事件寫在「事件｜畫面反應」表，「事件」欄寫 asyncapi.yaml 的 message 名稱。
- 每個呼叫都寫出成功時與失敗時的畫面反應；一個呼叫有多個錯誤碼且畫面反應不同時，另列「錯誤碼／畫面反應」表逐碼說明。

## Good Example
- 以 operationId 引用，成功與各錯誤碼的畫面反應分別寫出。

```
| 送出訂單 | `createOrder`，`expectedTotal` 帶畫面上的應付總額 | 前往 `complete.html` | 依下表處理 |

| 錯誤碼 | 畫面反應 |
| `PRICE_CHANGED` | 重新呼叫 `getCart`，以對話框顯示新總額 |
```

- 即時連線送出的操作另列一表，引用 asyncapi 的 message 名稱。

```
| 操作 | 送出訊息 | 受理時 | 拒絕時 |
| 訂閱購物車通知 | `subscribeCart` | 開始顯示售完與改價提示 | `SESSION_MISSING`：重新整理頁面 |
```

## Bad Example
- 寫 URL 而不是 operationId，失敗時只寫「顯示錯誤」，看不出各錯誤碼的差別。

```
| 送出訂單 | POST /orders | 前往完成頁 | 顯示錯誤 |
```

# Rule 3 - 四態與網址參數 [MUST]
- 每個畫面在「四態」寫出載入、空、錯誤、正常四態的呈現方式。
- 平常操作走不到的狀態（載入、錯誤、售完推播等），在「雛形」段的網址參數表列出 `?state=` 參數，每個參數對應一個可直接看到的狀態。

## Good Example
- 走不到的狀態都有參數，表中列出頁面、參數與呈現狀態。

```
| `index.html` | `?state=error` | `getCart` 失敗 |
| `index.html` | `?state=soldout` | 進入後 2 秒推播 `cartItemSoldOut` |
```

## Bad Example
- 只說明有錯誤狀態，沒有參數，review 的人看不到錯誤畫面。

```
- 錯誤時顯示錯誤訊息
```

# Rule 4 - 視覺風格的技術作法對照 research.md [MUST]
- 視覺風格段中有技術作法的項目（字型載入方式、外部資源、主題範圍）須符合 research.md 已定的安全與技術決策；例如 CSP 只允許同源時，不得寫外部字型服務。
- 使用者選定的風格與某條決策衝突時，在該項註明「與 R<n> 衝突」，並於 Phase 5 回報列為待呼叫端決定，不自行取捨。
- 雛形的字型載入方式與正式不同時（雛形為了雙擊可開而用 Google Fonts），在字型欄一併寫明「雛形以 Google Fonts 預覽」，讓下游知道差異是刻意的。

## Good Example
- research.md 的 CSP 只允許同源，字型欄寫自代管；主題與 R 節衝突時註明並交回呼叫端。

```
- 字型：標題用像素字體 `"Press Start 2P"`，中文與內文用 `"Noto Sans TC"`；字型檔自代管於 `public/fonts/`（R17 的 CSP 只允許同源；雛形以 Google Fonts 預覽）
- 主題：只提供深色（使用者選定）；與 R12 的「提供淺色 / 深色」衝突，待呼叫端決定
```

## Bad Example
- research.md 的 CSP 只允許同源，字型欄卻寫經外部服務載入；主題直接照使用者選的寫，沒有提 R 節的決策。

```
- 字型：標題用像素字體 `"Press Start 2P"`，中文與內文用 `"Noto Sans TC"`；皆經 Google Fonts 載入
- 主題：只提供深色
```
