# Rule 1 - 只收產出物內容的約束 [MUST]
- 憲法只收「產出物裡要寫什麼」的約束，例如回應欄位、命名、錯誤格式、資料表必備欄位。
- 下列不收，回報使用者並建議改 skill 或另開 skill：
    - 流程：步驟順序、要不要先寫測試、PR 與 CI 規定
    - 骨架：新增或刪除章節、改識別碼格式、決定要不要產出某個檔案

## Good Example
- API 錯誤格式是 openapi 的內容，收錄；「一定要先寫測試」是流程，不收並建議另開 skill。

```
「錯誤回應一律包在 error 信封內」 → 收錄 skills/api-plan/openapi.md
「一定要先寫測試」               → 不收；建議另開 test-plan skill
```

## Bad Example
- 把流程要求寫成 tasks.md 的條款，等於用憲法改 tasks skill 的流程。

```
skills/tasks/tasks.md
# Rule 1 - 測試任務排在實作任務之前 [MUST]
```

# Rule 2 - 約束只寫在最上游的產出物 [MUST]
- 下游 skill 照上游產出物實作的約束，只寫在上游產出物的檔案，不在下游重複寫。
- 例如 implement 照 schema.dbml 與 openapi.yaml 實作，資料表與 API 的約束只寫在 data-plan 與 api-plan。

## Good Example
- 稽核欄位只寫在 schema.md；implement 照 schema.dbml 建表即可。

```
skills/data-plan/schema.md
# Rule 1 - 每張表都有 created_at 與 updated_at [MUST]
```

## Bad Example
- 同一條約束在上下游各寫一份，日後修改容易漏改一邊。

```
skills/data-plan/schema.md      # Rule 1 - 每張表都有 created_at 與 updated_at
skills/implement/backend.md     # Rule 2 - 建表時加上 created_at 與 updated_at
```

# Rule 3 - 兩個以上 skill 的產出物都要直接遵守才放 shared [MUST]
- 一條約束要由兩個以上不同 skill 的產出物各自遵守，才寫入 `shared/`，並由這些產出物檔以 `- 引用：` 引用。
- 只屬於單一 skill 的約束，即使該 skill 有多個產出物，也寫在該 skill 的產出物檔。

## Good Example
- 敘述語言是 spec、research、plan、tasks 等多個 skill 的產出物都要遵守，放 shared。

```
shared/說明文字使用繁體中文.md
skills/specify/spec.md → - 引用：`shared/說明文字使用繁體中文.md`
skills/tasks/tasks.md  → - 引用：`shared/說明文字使用繁體中文.md`
```

## Bad Example
- 錯誤格式只由 api-plan 設計，卻放進 shared。

```
shared/錯誤格式.md
```

# Rule 4 - 依對照表決定檔名與 Applies To [MUST]
- 依下表決定約束寫入的檔案與檔首的 Applies To：

| skill | 檔案 | Applies To |
|---|---|---|
| specify（含 clarify-over-specs 回寫） | `skills/specify/spec.md` | `specs/*/spec.md` |
| technical-research | `skills/technical-research/research.md` | `specs/*/research.md` |
| technical-research | `skills/technical-research/techstack.md` | `specs/*/techstack.md` |
| system-analysis | `skills/system-analysis/plan.md` | `specs/*/plan.md` |
| ui-plan | `skills/ui-plan/frontend.md` | `specs/*/analysis/frontend.md` |
| ui-plan | `skills/ui-plan/prototype.md` | `specs/*/analysis/prototype/*.html` |
| api-plan | `skills/api-plan/openapi.md` | `specs/*/analysis/openapi.yaml` |
| api-plan | `skills/api-plan/asyncapi.md` | `specs/*/analysis/asyncapi.yaml` |
| data-plan | `skills/data-plan/schema.md` | `specs/*/analysis/schema.dbml` |
| tasks | `skills/tasks/tasks.md` | `specs/*/tasks.md` |
| implement | `skills/implement/<工作區>.md` | `<工作區>/**` |

- implement 依 repo 頂層工作區各一個檔，例如 `frontend/`、`backend/`。

## Good Example
- 後端日誌規則寫在 backend 工作區的檔案。

```
skills/implement/backend.md
- Applies To：`backend/**`
```

## Bad Example
- 前後端程式碼的約束混在一個檔，Applies To 也無法對應單一工作區。

```
skills/implement/code.md
- Applies To：`**/*.ts`
```
